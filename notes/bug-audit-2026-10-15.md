# Bug audit, 2026-10-15

Audited on branch `claude/bug-audit-0c565a` (base `8712c7c5`, after #243). A read of the whole
source tree for correctness bugs, in five parallel passes (core; server; providers and
standards; hub, community, evals and the command line; the dashboard), each candidate then
reproduced against the code before it was fixed. Lint, formatting, mypy and the core suite were
clean at the start. No real data was involved; nothing was run against a deployment.

**Wrong answers**

- `providers/cql.py`: a definition the engine never returned was read as null, a confident
  `unknown` (0.98); it is `invalid_response`.
- `providers/vote.py`: an infinite weight (YAML `.inf`) made every probability NaN.
- `evals/gate.py`: the gate compared only the change's critical labels, so a label dropped from
  `evaluation.critical` (or left without a labelled case) passed; so did a primary accuracy that
  became `None`. The registry's regression check and CI's pack gate both relied on it.
- JSON Lines readers (`evals/harness.py`, `core/evalsets.py`, `standards/bulk.py`,
  `community/phi_scan.py`) used `str.splitlines`, which breaks a line at U+2028, U+2029 and
  U+0085; `json.dumps(ensure_ascii=False)` (the feedback export) leaves those raw inside a
  string, so an exported dataset would not load again.
- `core/audit.py`: `consume` and `consume_org` counted the first call of a day before checking a
  limit of 0 (the INSERT path has no guard), so usage said one was made.
- `community/check.py`: the PHI scan read `data/` and `tests/` only; a dataset the manifest
  names elsewhere was never scanned. `phi_scan.py` also missed `(212)555-1234` and
  `123 45 6789`.

**Server**

- A negative `limit` on `/api/audit`, `/api/review`, `/api/feedback`, `/api/deployments`:
  SQLite reads `LIMIT -1` as no limit (every row, past the 500 cap, each input read and chained
  under PHI mode); Postgres answers 500. Reproduced locally. Clamped at 0.
- `/api/health` gave a scoped key or token the deployment's detail (allow-lists, key ids,
  quotas, holds); a scoped credential reaches only the routes its scope names. Now public only.
- `HEAD` resolved to `admin` because the rules name GET: an anonymous `HEAD` on a static file
  (which serves HEAD as GET) was a 401, and `HEAD /` a 401 instead of the sign-in redirect.
- The OIDC login appended `?query` to an authorization endpoint that already had a query.
- Claims mode left the browser's earlier session row live after a new sign-in; memberships mode
  already deleted it.

**Dashboard**

- `audit.js`: a slow `/api/audit/{id}` reply replaced a newer drawer (and under PHI mode chained
  an `input.read` for a record the person did not open); a slow list reply painted over a newer
  outcome filter. Latest request wins, in both.
- `main.js`: a pack whose details failed to load (503, or 403 in memberships mode) left the
  previous pack's view on screen with the new pack selected, and an unhandled rejection. The
  error view with Try again shows instead.
- `evals.js`: a run finishing after the tab was left threw on detached elements, and a failed
  run's toast was lost.
- `charts.js`: a log axis over no positive value looped forever (latent: no caller reaches it).
- `form.js`: a numeric enum was sent back as a string (latent: no shipped pack has one).

## Found, left for the owner (behaviour decisions, not fixes)

1. **`record_outcome` overwrites a reviewer's final label** (`core/audit.py`, `record_outcome`).
   The docstring says an outcome is ground truth for a decision that was *not* reviewed, and a
   `pending` review is refused, but a `resolved` one is accepted: the reviewer's `final_label` is
   replaced while `human_override`, `reviewer` and `resolved_at` keep describing the label that
   is gone, and `stats()` flips. Either refuse an outcome on a resolved decision, or say that a
   later outcome wins and keep the reviewer's label in its own column. This changes what the
   audit chain records about clinical decisions, so it is the owner's call. *Decided the same
   day: keep both. The outcome is the decision's `observed_label`, the review's columns never
   change after the review, and older rows are put right from the chain (PR #246).*
2. **Lifting an automation hold is one click** (`card.js`). Every other destructive action goes
   through the confirmation dialog; Lift is the one action that raises automation.
   `tests/browser/test_hold.py` pins the one-click behaviour.
3. **The Access view's Activity tab shows the oldest 5,000 events of 90 days, not the newest**
   (`admin.js`): it pages oldest-first and stops at the cap. The note under the table says so;
   newest-first paging or a narrower window would fix it.
4. **A cookie-bearing top-level GET from a browser without Fetch Metadata passes the origin
   check** (`server/origin.py`): no `Sec-Fetch-Site`, no `Origin`, so it reads as a script. The
   module's docstring treats that case as intended; Safari before 16.4 is the browser it affects.
5. The PHI heuristics do not flag a bare 10-digit phone number or a textual date of birth
   ("January 2, 1980"); widening them risks flagging MRNs and ordinary dates. Scope, not a bug.
