# Bug and dead-code audit, 2026-11-27

Audited at `dc7ab649` (`main`, after 0.1.1), fixed on `audit/bugs-dead-code`. Two halves:

- **Dead code, measured.** vulture over `src/` and `scripts/` (once with the tests counted as
  users, once without: what nothing uses, and what only tests use); the whole suite under branch
  coverage on SQLite and Postgres (8,317 passed; 95% of 37,633 statements; 32 functions never
  entered); mypy's unreachable-code check; ruff's unused-argument, blanket-except, loop-variable
  and subprocess rules; deptry. Each candidate was then checked by hand (every use searched for,
  dynamic ones included) before anything was removed.
- **Bugs, read.** Seven parallel reviews: core's logic; core's stores and audit chain; the
  server; evaluation and providers; the registry and the healthcare standards; the command line,
  install and scripts; the dashboard and the Agent Hub site. Each finding came with a
  reproduction (or, in the front ends, a traced data path), and each reproduction was run again
  independently before anything was fixed. Then seven parallel fixes, one per area in its own
  worktree, each test first: a test that fails on `main` for the finding's reason, then the fix.

No real data was involved; nothing was run against a deployment. No finding was high: none
raised automation, released an action, or exposed another organization's data.

**Wrong answers**

- `core/audit.py`: a full `verify` on a live database read the chain's head, then the grading
  rounds, store versions and notes, outside one snapshot: a grade recorded meanwhile looked
  unchained, so the System checks raised a false "audit trail broken" alert. It reads one
  snapshot now (one read transaction under WAL; `REPEATABLE READ, READ ONLY` on Postgres).
- `core/written.py`: `verify` never compared a stored grade's grader with the one its event
  chained, so a grade given to another clinician in the database verified, and closing the
  round credited them in a report then chained and served. `verify` checks the grader; closing
  checks the round's grades against the chain first and refuses.
- `server/system.py`, `server/app.py`: a forged checkpoint statement in the database was
  reported as a broken chain, and "Signed checkpoint" said ok for it; the statement is checked,
  and its failure has its own words.
- `hub/registry.py`: a key or publish token revoked while a publish was checked did not stop
  it: the version was stored, listed and counter-signed. Both are checked again inside the write.
- `hub/registry.py`, `core/registry.py`: `version_key` ties a release and its pre-releases (on
  purpose: a pre-release may not take a reference agent's place), and the newest version was
  whichever was found first among those that tie: `1.0.0-rc.1` stayed the registry's latest over
  `1.0.0`, and an engine served `rc.1` over `rc.2`. Both order versions by SemVer precedence.
- `providers/http.py`: an attempt could run two or three times its deadline (each network step
  had the whole timeout), past Vercel's limit; every step now waits at most what remains.
- `standards/bulk.py`: a 429 while polling an export failed it; it is waited out.
- `mcp.py`: `mendari mcp` automated an agent from a registry that a running server holds until
  its registry's recalls are read; it uses the server's recall watch.
- `cli.py`: `audit export --since` compared the typed text with stored times as strings: the
  backup-name form (`20261127T000000Z`), which the restore runbook uses, exported nothing.
- `core/phi_detect.py`: a phone number right after a fictional one was missed.
- `core/agent_store.py`: `store verify` crashed with a `KeyError` if a purge committed during it.
- `agent_kit.py`: the kit accepted a `service_version` ending in a newline that the engine refuses.
- `cli.py`: `--limit` 0 meant no limit and a negative one cut cases off the end (`eval`,
  `calibrate`, `leaderboard`, `written`); options a run would ignore are refused (`eval
  --ticket`, `--supersedes`, `--consent-remote` unshared, `--supersedes` beside a ticket,
  `--registry` unshared and unpublished; `leaderboard --run` without `--dataset`, and its run
  options without `--run`; `sandbox smart-launch --limit` below 1).
- Dashboard: the record drawer's same-agent guard read a field the record never has, so another
  agent's decision was offered for replay into the chosen agent's Try it; the replay's note was
  always empty; the audit trail listed the newest 100 decisions without saying so, and its
  search found nothing beyond them; a failed read of the holds read as "no holds"; the palette
  offered to open an id prefix the record route cannot find.
- Agent Hub: a `risk` filter that is not a number read as a registry outage.

**Core logic**

- `core/decision.py`: NaN or an infinity in an input passed the schema (no comparison with NaN
  is true): a canned answer automated it with NaN in the record, and a live agent's call raised
  (a 500, nothing recorded). It is an input problem now, refused before the schema runs: the
  decision is a recorded BLOCK, owned or bounded.
- `core/decision.py`: one `required` keyword gave an owned agent one identical reason per
  missing name, filling the ten reasons and pushing the input's other problems out; each reason
  is listed once, as a bounded agent's always were.
- `core/spec.py`, `core/templates.py`: a question named `recommendation` or `priority` (a
  built-in placeholder) loaded, and the card summary's length check and its rendering filled the
  placeholder with different values, so the length check could be passed with a summary too
  long; it is refused at load.
- `core/policy.py`: the canned cap's reason came before the site code's and the limits' when the
  decision had already gone to a person; the reasons follow the steps' order on every path.
- `core/re2_syntax.py`: a non-multiline `$` with more of the pattern after it matched differently
  on RE2 (an agent from a registry) than on Python's `re` (the same agent run as one's own); it
  is refused on RE2, naming `\Z` or `\n?\Z`. A word boundary between two non-ASCII word
  characters inside a match can still differ: the docstrings and the authoring guide say so
  exactly, since a refusal would also reject ordinary patterns such as `\b\d+\b\s*mg`.

## Found, left for the owner

- `cryptography` reaches the install only through `pyjwt[crypto]` (deptry): fine while that
  extra is declared; a floor of its own would guard against an old copy already installed.
- The attempt budget sets httpcore's network backend on httpx's pools, which httpx does not
  expose: a test fails if an upgrade moves it. Name lookup is still not bounded (threat model D9).
- A long `verify` now holds one read transaction: on SQLite the WAL cannot be checkpointed past
  it until it ends; on Postgres it holds back vacuum for that time.
- A token revoked while a request is in flight can finish that one request (the publish, the
  most consequential, is checked again in its write).
- A decision refused for NaN in its input still records the input as given: the stored record
  holds a `NaN` token (the API serves it as null, and the chained digest covers it). Nothing
  breaks; writing null instead would change what is hashed.
- On an empty text, RE2's `\B` matches and Python's does not (the one difference the reviewers'
  fuzzer still finds).
- Three timing-bound tests in `tests/test_bounded_budget.py` failed once in a heavily loaded
  run and passed on every rerun: their CPU bounds are tight on a busy machine.
