Healthcare decisions you can test, trust and share.

Mendari packages everyday decisions in care, like routing a patient’s message or checking a referral, as Decision Packs: versioned, evaluated on data, and built to hand the hard cases to a person.

See the packs How it works

Every decision ends in one of four outcomes.

A pack answers its questions with rules, classical models, Jev or a language model. Its policy turns the answers into an outcome, and the outcome says what to do. Policy can only lower automation, never raise it.

  • AUTO

    Automated

    Acted on without a person, within the pack’s policy.

  • HUMAN_REVIEW

    Human review

    A person decides, with the pack’s recommendation.

  • ABSTAIN

    Abstained

    Not confident enough to say.

  • BLOCK

    Blocked

    The input or a safety rule stops it.

Every decision is written to an append-only, hash-chained audit trail. One that needs a person waits in the review queue, and each can be read as a FHIR Task.

Scored before it ships. Same cases, each model.

Every configuration of a reference pack is scored on the same labelled cases, so what a model adds can be measured before you pay for it. Mendari doesn’t depend on any one model: swap rules, naive Bayes, Jev, a hosted LLM or one you run yourself.

Each figure is k of n with its exact 95% interval. A public set is a regression check, not a ranking: grades and rankings are given only on frozen hidden sets.

  • Your pack

    A pack is a folder of plain-text files. Write one without programming and test it on synthetic data.

    mendari new refill-router --id my-clinic/refill-router

Benchmark results on each pack’s synthetic test set. Template-generated data overstates real-world accuracy: validate on your own labelled cases before any use.

One pack, read three ways.

Developers

Build a pack, test it, and see what each model adds.

  • Scaffold, test and evaluate with mendari new, test and eval
  • Compare providers on the same cases with mendari leaderboard
  • OpenAI-compatible models with structured output, including ones you run yourself

Health professionals

Know what a pack is for, how it scored, and when it hands off.

  • A Decision Card for every pack: intended use, population, out of scope, results as k of n
  • Uncertain cases wait for a person in a queue sorted by priority
  • Reviewers mark any decision right or wrong, with the right answer

IT & informatics

Check it on your data, govern what runs, and audit every call.

  • Validate on your own labelled cases; fail the run if results degrade
  • Risk-level limits enforced at runtime; sign-in with roles
  • Hash-chained audit trail, checked with mendari audit verify

Try every pack on synthetic data.

The demo runs the Patient Inbox Router end to end, including the message above: decisions, the review queue, the audit-chain check and local validation. Then mendari serve opens the API and the dashboard with every reference pack, its scores and its Decision Card.

The source opens to the public at launch. Until then, cloning needs access to the repository.

TerminalPython 3.11+, uv

$ git clone https://github.com/mendari-hq/mendari.git
$ cd mendari
$ uv sync
$ uv run mendari demo
$ uv run mendari serve   # http://127.0.0.1:8000
