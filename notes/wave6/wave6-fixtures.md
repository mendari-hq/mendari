# Wave 6 fixtures: the synthetic agents the tests use

Every fixture here is synthetic, generated deterministically, and labelled "Synthetic test
fixture. Not clinically reviewed. Not for patient care." in its manifest's `card` and
`summary`. Fixture ids use the namespace `mendari-test/`, as `actions-mini` and `written-mini`
already do.

## 0. Where they live, and how tests reach them

- **Folder.** During Phases 1 and 2 the new fixtures live one level deep in
  `tests/fixtures/reference-agents/`. That folder is today's bundled directory
  (`conftest.py:50-52`), and `core/reference.py` reads only one bundled directory, so the new
  fixtures sit beside the five former packs while tests move. Phase 3 deletes the five and
  renames the folder `tests/fixtures/agents/`.
- **No literal paths.** Tests use the `conftest` constants and fixtures only. Literal paths are
  forbidden, so the folder rename touches `conftest.py` and the CI files only.
- **One generator.** `tests/support/fixture_agents.py` (new) writes every generated file:
  - `uv run python -m tests.support.fixture_agents` writes;
  - `--check` compares with the committed files;
  - `tests/test_fixture_agents.py` runs `--check` and replaces `test_fixture_data.py`.

  Each fixture has a fixed seed (`random.Random("triage")` and so on) and fixed phrase lists. No
  date, clock or environment is read.
- **Generator scope.** It writes datasets (JSONL) and, for F3, FHIR. Manifests, rules, schemas,
  mock files and behaviour tests are hand-written.
- **`conftest.py` replacements:**

  | Old | New |
  |---|---|
  | `INBOX_DIR` | `TRIAGE_DIR` (also `CLINICAL_DIR`, `CHART_DIR`, `FIXTURE_AGENTS`) |
  | `inbox_pack` | `triage_agent` (session) |
  | `router` | `triage` (a `Decision`) |
  | `pack_copy` | `agent_copy(manifest=..., policy=..., agent=TRIAGE_DIR)` (copies with tiny datasets, as today) |
  | `calm_jev` and `screened` | `calm_agent(monkeypatch)`: points `MENDARI_AGENT_URL` at `https://agent.test/v1/decide` and puts an `httpx.MockTransport` where the provider's call is, answering F1's questions confidently and calmly. It returns `{"screen": "agent", "router": "agent"}` for the tests that need AUTO with sign-in on, where canned answers never automate |
  | `shared_benchmark()` | Evaluates F1's `test` set once per session; no committed ledger |
  | `Registry.publish()` default | F1 |

  The `registry` fixture creates the namespaces `mendari` and `mendari-test`.

## F0. The demo agent, `agents/portal-message-agent` (existing, read-only)

**Use it where a test checks the shipped product:** the demo, the quickstart, the CI action,
the committee packet, the operating point, the written-output demo, docs snippets, packaging,
the image, the sandbox and the Hub seed.

**Do not use it for engine tests.** Its data is product, regenerated by
`scripts/demo_agent_data.py`, and its figures appear in the README. Engine tests that pinned
its numbers would break whenever the demo agent improves.

**Tests onto it:** `test_sandbox`, `test_smart_launch`, `test_cds_client_sandbox` (the
vendor-profile half goes with G6), and the files already on it.

## F1. `mendari-test/triage`: the workhorse

**Replaces** `patient-inbox-router` everywhere, and `referral-router`, `ai-guard`,
`clinical-trial-prescreener` and `prior-auth-preflight` wherever they only stood for "an agent".

**What it exercises:**

- spec 0.4;
- risk level 1;
- two slots, so batching, `automation_requires` and per-slot provider selection;
- `agent` (canned, keyword-matched, `service_id`), `rules`, `llm` (faked endpoint), the `check`
  composite (agent checked by rules) and `repeat`;
- a three-question policy: rules to `HUMAN_REVIEW` with a recommendation and priority, and to
  `BLOCK`;
- thresholds, `allow_auto: false` and `auto_threshold` per label, a critical label;
- `display` and `names`, `card.evidence`, a subgroup;
- a FHIR mapping (Communication in, Task out with a performer system);
- a CDS hook with card templates (`summaries`, `indicators`, `show`, `also_show`, `refused`);
- datasets of 300 and 200 cases (publishing and site reports need 100 or more; calibration
  needs 100 per question);
- behaviour tests, enough for the store, the registry, archives, sites, monitoring and the
  console.

**Every outcome deterministic offline:**

- `AUTO`: refill or billing-free cases at 0.95 with `screen=agent`;
- `HUMAN_REVIEW`: 0.70 to 0.89, or a rule;
- `ABSTAIN`: below 0.50;
- `BLOCK`: a schema failure, or the `abusive-message` rule.

**Manifest outline:**

```yaml
spec_version: "0.4"
id: mendari-test/triage
version: 1.0.0
name: "Synthetic Triage (test fixture)"
summary: >-
  Synthetic test fixture. Routes a synthetic patient message to the team that reads it first
  and flags same-day symptoms. Not clinically reviewed. Not for patient care.
publisher: {name: Mendari tests, type: community}
license: Apache-2.0
risk: {level: 1, category: clinical information, rationale: Test fixture.}
card:
  provenance: synthetic
  intended_use: Tests of the engine.
  intended_users: [Mendari developers]
  patient_population: Synthetic messages.
  evidence: [{title: Synthetic data only, note: Generated by tests/support/fixture_agents.py.}]
inputs: {schema: schemas/input.schema.json, fhir: fhir/mapping.yaml}
questions:
  destination:
    display: Team
    instructions: Which team should read the message first?
    criteria: {front_desk: ..., nurse: ..., pharmacy: ..., billing: ...}
    names: {front_desk: Front desk}
  urgency: {type: boolean, instructions: Same-day symptoms?, criteria: {"yes": ..., "no": ...}}
  abusive: {type: boolean, instructions: Is the message abusive?, criteria: {"yes": ..., "no": ...}}
providers:
  router:
    answers: [destination]
    use: agent
    variants:
      agent: {type: agent, service_id: triage-router, state_fields: [message.subject, message.body],
              mock_file: fixtures/router.json}
      rules: {type: rules, config: logic/router_rules.yaml}
      llm: {type: llm, state_fields: [message.body]}
  screen:
    answers: [urgency, abusive]
    use: rules
    variants:
      rules: {type: rules, config: logic/screen_rules.yaml}
      agent: {type: agent, service_id: triage-screen, state_fields: [message.body],
              mock_file: fixtures/screen.json}
      checked: {type: check, members: {agent: {type: agent, service_id: triage-screen,
                state_fields: [message.body], mock_file: fixtures/screen.json},
                second: {type: rules, config: logic/screen_rules.yaml}}}
      repeated: {type: agent, service_id: triage-screen, state_fields: [message.body],
                 mock_file: fixtures/screen.json, repeat: 3}
policy:
  primary: destination
  thresholds: {auto: 0.90, review: 0.50}
  labels: {billing: {allow_auto: false}, front_desk: {auto_threshold: 0.95}}
  automation_requires: {screen: [agent, checked]}
  rules:
    - {name: possible-emergency, when: {question: urgency, labels: ["yes"], min_probability: 0.35},
       outcome: HUMAN_REVIEW, recommendation: nurse, priority: stat, reason: ...}
    - {name: abusive-message, when: {question: abusive, labels: ["yes"], min_confidence: 0.9},
       outcome: BLOCK, reason: ...}
  fallback: The front desk reads the message.
  default_priority: routine
evaluation:
  datasets: {examples: data/examples.jsonl, test: data/test.jsonl,
             calibration: data/calibration.jsonl, critical: data/critical.jsonl}
  benchmark_dataset: test
  critical: [{question: urgency, label: "yes"}]
  subgroups: [message.channel]
tests: tests/cases.yaml
cds_hooks:
  hook: mendari-message-received
  title: Synthetic Triage
  description: Test fixture.
  prefetch: {communication: "Communication/{{context.communicationId}}",
             patient: "Patient/{{context.patientId}}"}
  card:
    summaries: {nurse: "...{priority}...", front_desk: ..., pharmacy: ..., billing: ...,
                none: ..., refused: ...}
    indicators: {nurse: critical}
    show: [nurse, pharmacy, front_desk, billing]
    also_show: {possible-emergency: {summary: ..., indicator: critical}}
```

**Files:**

- `schemas/input.schema.json`: `message.{subject, body, channel}`, closed.
- `fhir/mapping.yaml`: Communication in (topic, payload, medium coding into `message.channel`
  using the sandbox's message-channel system); Task with `performer_system:
  https://mendari.co/fhir/CodeSystem/fixture-triage-team`.
- `logic/router_rules.yaml` and `logic/screen_rules.yaml`: keyword rules, some negatable, all
  RE2-safe.
- `fixtures/router.json` and `fixtures/screen.json`: canned answers by keyword. Confidences
  are 0.95, 0.75, 0.40 and a default, with `service_version: 2.0.0`.
- `tests/cases.yaml`: about 10 behaviour tests.
- `data/`: generated.

**Data, generated:**

- `examples` (12), `test` (300), `calibration` (200), `critical` (40 urgent cases worded as a
  patient might, so the rules miss some on purpose, for the operating point and the safety
  invariant).
- Built from four destination phrase lists, an urgent-symptom list with negations ("no chest
  pain"), a paraphrased-urgent list the rules do not match, a mild synthetic-abuse list, and
  three channels.
- Labels come from the generator's own facts, never from a provider.
- About 1,000 lines of JSONL.

**Tests onto it:** the 153 F1 files of `wave6-inventory.md` section 1.14, by area:

- Engine: decision, policy, providers, spec (`test_spec_02` merges into `test_spec`), manifest,
  agent content and isolation, input schema, patterns, text, templates, the bounded engine
  (`test_community_{budget,caps,re2}` → `test_bounded_*`), `llm` and batching, deadline,
  second signal, calibration, safety invariant.
- Evaluation: evals, ledger, figures, ranking, gate, leaderboard, coverage, dataset checks,
  validation, validation brief, monitoring, feedback, reviewed cases, outcomes.
- Platform: audit, auth, memberships, tenancy, two organizations, PHI, rotation, hosted data,
  notes, holds, limits, usage, alerts, sessions, security log, readiness, restore.
- FHIR, CDS and SMART: FHIR routes and search, `$decide`, capability, Task, AuditEvent,
  terminology, the CDS cards, clients, feedback and open mode, SMART.
- Registry and sharing: registry, archive, hub client and routes, acceptance, claims, tokens,
  yank, chain, checkpoint, regression, sites, tickets, site reports, share, site evidence.
- Store: agent store, uploads, jobs, promotion, improvement, connections, key presets.
- Browser: all 20 rewritten browser files.

## F2. `mendari-test/clinical-review`: risk level 2, with a score question

**What it exercises:**

- risk level 2: AUTO only under a recorded governance approval;
- the `pilot-check` CI job's `--approve`;
- level 3 and 4 caps, through `agent_copy` edits;
- a `score` question in a policy rule (`min_score`), which replaces `trial-mini`;
- a critical label on the primary question;
- the committee packet's approval section.

**Manifest outline:**

```yaml
spec_version: "0.4"
id: mendari-test/clinical-review
version: 1.0.0
risk: {level: 2, category: clinical support, rationale: Test fixture.}
questions:
  disposition: {instructions: ..., criteria: {self_care: ..., book_visit: ..., see_today: ...}}
  severity: {type: score, instructions: ..., levels: {none: {score: 0, criterion: ...},
             mild: {score: 1, ...}, moderate: {score: 2, ...}, severe: {score: 3, ...}}}
providers:
  reader: {answers: [disposition, severity], use: agent,
           variants: {agent: {type: agent, service_id: clinical-review, mock_file: fixtures/mock.json,
                              state_fields: [note.text]},
                      rules: {type: rules, config: logic/rules.yaml}}}
policy:
  primary: disposition
  thresholds: {auto: 0.9, review: 0.5}
  rules: [{name: moderate-or-worse, when: {question: severity, min_score: 2}, outcome: HUMAN_REVIEW,
           priority: urgent, reason: ...}]
  fallback: A clinician reads the note.
evaluation: {datasets: {examples: data/examples.jsonl, test: data/test.jsonl}, benchmark_dataset: test,
             critical: [{question: disposition, label: see_today}]}
tests: tests/cases.yaml
```

**Data, generated:** `examples` (12) and `test` (120) synthetic triage notes, from symptom ×
duration × severity phrase lists.

**Tests onto it:** `test_governance`, `test_pilot_check`, and the risk-level cases of
`test_policy`, `test_packet` and the store's promotion tests. CI: `pilot-check --approve
tests/fixtures/agents/clinical-review`.

## F3. `mendari-test/chart-summary`: a FHIR record in, a `patient-view` hook

**What it exercises:**

- a mapping with `focus: Patient`, `fields` (with the `age_years` and `join` transforms) and
  `lists` (Condition, MedicationStatement);
- the `patient-view` CDS hook with search prefetch;
- US Core checks on a record;
- the structural R4 gate on Bundles;
- data coverage of lists;
- unreadable prefetch → ABSTAIN;
- a patient-level Bulk export evaluated like its dataset;
- `$decide` with a Bundle;
- the FHIR golden decisions.

**Manifest outline:**

```yaml
spec_version: "0.4"
id: mendari-test/chart-summary
risk: {level: 1, category: clinical information, rationale: Test fixture.}
inputs: {schema: schemas/input.schema.json, fhir: fhir/mapping.yaml}
questions:
  follow_up: {instructions: ..., criteria: {none: ..., routine: ..., soon: ...}}
  on_anticoagulant: {type: boolean, ...}
providers: {reader: {answers: [follow_up, on_anticoagulant], use: agent,
            variants: {agent: {type: agent, service_id: chart-summary, mock_file: fixtures/mock.json,
                                state_fields: [patient.age, conditions, medications]},
                       rules: {type: rules, config: logic/rules.yaml}}}}
policy: {primary: follow_up, thresholds: {auto: 0.9, review: 0.5}, fallback: A clinician reads the chart.}
evaluation: {datasets: {examples: ..., test: data/test.jsonl}, benchmark_dataset: test,
             critical: [{question: follow_up, label: soon}]}
cds_hooks:
  hook: patient-view
  prefetch: {patient: "Patient/{{context.patientId}}",
             conditions: "Condition?patient={{context.patientId}}",
             medications: "MedicationStatement?patient={{context.patientId}}"}
  card: {summaries: {soon: ..., routine: ..., none: ...}, show: [soon, routine]}
```

**Data, generated:**

- `test` (120) synthetic patients: input JSON with the record's case id.
- `tests/support/fixture_records.py` (new; replaces the tests' `fhir_records.py`) builds each
  case's US Core Patient, Conditions and MedicationStatements as a Bundle, deterministically
  from the case. It uses fictional-free codes: ICD-10-CM conditions, RxNorm drugs. No SNOMED CT;
  `check_snomed` and `test_code_systems` stay green.
- `tests/fixtures/us-core/chart.json` and `invalid/chart.json` (for `fhir_validate.py
  --valid/--invalid`) and `triage.json` (F1's Communications) are written by the generator.

**Tests onto it:** `test_bulk`, `test_cds_unreadable`, `test_data_coverage`, `test_fhir_lists`,
`test_fhir_structure`; the record parts of `test_us_core`, `test_decide_op` and
`test_fhir_decisions`. CI: `fhir-conformance` and `terminology.yml` use
`--fixture chart=tests/fixtures/agents/chart-summary`.

**If G6 keeps record reading,** F3 also gets: `paths`, a `[system=…]` predicate, `follow`
(`medicationReference`), `code_sets`, `attachment_text` (DocumentReference notes), a site code
map, an EHR declaration, and an order hook (`order-sign` on a ServiceRequest). Then
`test_fhir_linked`, `test_fhir_mapping_03`, `test_site_codes`, `test_order_sign` and
`test_epic_data_fit` (narrowed) move onto it.

## Checks a fixture must pass

1. `mendari validate`, `mendari test` and `mendari eval --dataset test` on each.
2. The generator's `--check`.
3. `tests/test_safety_invariant.py` (no critical case automated in any configuration that needs
   no service).
4. `tests/test_code_systems.py`, which forbids licensed code systems.
5. CI step "The test fixtures' agents pass their behaviour tests" over `tests/fixtures/agents/*`.
